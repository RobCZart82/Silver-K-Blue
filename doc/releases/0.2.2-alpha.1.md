# Silver-K 0.2.2 Alpha 1

Host state reads and KS diagnostics no longer pause the firmware worker. K-Station and KS publish preset/Flash snapshots; completed Flash writes refresh reusable cache storage. Redundant host preparation with unchanged rate/block preserves the running engine. Both workers join the host audio workgroup where available, use a block-based realtime period and enter realtime priority after boot/JIT warm-up. K-Station also refills its audio queue before leaving offline warm-up.

Setup now offers Low latency, Balanced (default), Safe and Maximum reserve. Switching changes the scheduling reserve without restarting firmware or clearing voices/effects. Plugin latency is shown in milliseconds; the audio interface buffer remains a DAW setting. Low latency uses a smaller reserve and can still underrun during cold JIT or CPU overload. Original sonic algorithms remain firmware-based.

The main folder defaults to Documents/Silver-K, with ROMs for external firmware, KS Data and Wave ROM, and Patches for bank files. Selecting a main folder generates our synthetic Init Flash and zero Wave ROM only if absent. The firmware catalog is remembered after its first scan; startup restores it without enumerating ROMs or decoding archives. Rescan ROMs explicitly updates it. Actual firmware contents and project asset hashes are still validated when loading. Relative asset paths and legacy projects are supported; the metadata database retains existing favourites/tags in its existing location (on macOS, ~/Library/The Usual Suspects/Silver-K).

Patch management supports single-click loading and all six sort columns. The supplied EDM_Underworld_DEMO_XS.zip contains a legacy V-Station NvS0/FBCh bank with 400 slots. Its 128-byte sound blocks are imported unchanged as K programs, names and slot identity are retained, and a V-Station tag is added. Direct FXB and ZIP import are supported. KS uses the existing K conversion with its 16-character firmware name. Re-adding an already loaded source no longer duplicates its rows. Other FXB layouts and FXP are outside this importer.

Local macOS arm64 verification:

- The preceding 0.2.1 build passed six 12-second live tests: K/KS at 48 kHz with 64, 128 and 256-sample host blocks, eight-note keyboard bursts and state reads every 100 ms. All had zero startup and steady missed frames with Balanced. The 128-sample tests also changed reserves while playing and prepared the same host rate/block from a control thread.
- The final 0.2.1 state/import changes passed both 128-sample live tests again with zero missed frames. Reported initial latency: K 10.54 ms; KS 10.67 ms. First-note onset in the controlled fixture: K 14.54 ms, KS 14.73 ms. Physical MIDI/audio-driver delays are additional.
- The 0.2.2 build passed four additional 12-second live checks, all with zero startup and steady missed frames. With an AU-like preparation maximum of 1024 and actual 128-frame callbacks, Low latency adapted from 26.33 to 7.92 ms in K and from 24.00 to 5.33 ms in KS. The initial note at 100 ms still used the original queue reserve; later reporting reflects the settled reserve. Balanced with 128-frame preparation also passed both engines while switching to Safe/Maximum and repeating host preparation. All four checks read state every 100 ms during fast eight-note keyboard bursts. The macOS command-line fixture pumps the CoreFoundation message source on its main thread so processor timers run as they do inside an AU host.
- Original firmware arp at 90/180 BPM retained note spacing during Pulse changes and state reads; checked callbacks had zero C++ allocations.
- Actual AU and VST3 wrappers passed host-clock/Pulse tests. Their four-second captures added zero underruns. KS cold load/warm-up did record underruns (AU 7298 frames; VST3 4703); these were outside the steady captures, so these results do not promise glitch-free cold JIT or overloaded projects.
- All 400 V-Station slots matched the archive's names and sound bytes. Both browsers retained 400 rows and loaded BAS-Bittersweet on selection. All 16 demo sounds produced finite audible output in K and KS with no C++ callback allocations. K firmware retained mapped sound fields; KS received the patch name.
- Four scoped CTest checks passed: conversion, host clock, patch workflow, KS part MIDI. Malformed FXB rejection, cached ROM catalog, folder persistence and all four Setup buffer choices are included. External dependency test targets were not built in this local plugin validation.

Release archives contain our synthetic Init Flash and zero Wave ROM, documentation, notices and an actual source snapshot including local changes. Original firmware, factory banks, the private V-Station archive and sampled Wave ROMs are not distributed. macOS bundles are locally ad-hoc signed and are not notarized. Windows code remains supported by the build workflow; this change was validated locally on macOS arm64.

An additional Logic check found that AU prepares a 1024-frame maximum even with a physical I/O buffer of 128. Low latency now uses the largest observed callback slice in each message-thread observation window instead of this maximum. Buffer reporting and shrinking happen on the message thread; a larger slice raises the reserve through bounded atomics in the audio callback. Balanced/Safe/Maximum retain the host maximum for conservative playback. A sudden block-size increase or CPU overload can still outrun Low latency's reserve; use Balanced or higher if needed. The host's physical I/O buffer is unchanged. The buffer choice persists in project state.
