# Silver-K — тест H8 / C++ на Windows x64

Экспериментальная сборка ветки Optimized для сравнения на Ryzen 3 3100,
Windows 11. В архиве VST3 и Standalone; версия плагина остаётся 0.2.4.
Исходники именно этой сборки находятся в `Silver-K-source.zip`, идентификаторы
и контрольные суммы — в `release-manifest.json`, `SOURCES.txt`, `SHA256SUMS.txt`.

## Запуск

1. Распакуйте архив. Standalone: `Standalone/Silver-K.exe`.
   Для VST3 закройте DAW и установите целиком папку
   `Plugins/VST3/Silver-K.vst3` по инструкции `INSTALL.md`.
   Идентификатор плагина совпадает с обычным Silver-K; сохраните предыдущую
   сборку отдельно, вне папки сканирования плагинов.
2. Используйте свои прежние OS, KS Data и Wave ROM. Новая прошивка не нужна.
   Для C++ требуется KS OS 2.1.02. Оригинальная прошивка и заводские банки
   в архив не входят. Приложенные тестовые Data и нулевая Wave ROM нужны
   только для первого запуска без своих данных; ими не нужно заменять
   существующие банки. Нулевая Wave ROM не воспроизводит семпловые волны.
3. Откройте **Setup → KS controller**:
   **H8 (original)** — исходный контроллер;
   **C++ (experimental)** — оригинальная загрузка DSP, затем живой C++.
   Переключение сохраняет текущий звук, голоса и sustain; перезагрузка
   прошивки не требуется. Для сравнения CPU переключайте при остановленном
   транспорте, затем запускайте одну и ту же MIDI-партию с начала.
4. Без прежних экспериментальных настроек первым выбирается H8. Выбор
   запоминается для новых экземпляров и отдельно в проекте DAW. Старые
   проекты без этого поля открываются с H8. В K-Station переключатель
   неактивен. Неподдерживаемая C++ прошивка выдаёт ошибку; при отказе
   переключения работающий H8 сохраняется.

## Сравнение

- Начните с одной копии KS, одного и того же пресета, MIDI, частоты,
  аудиобуфера и профиля **Audio buffer**. Сравнивайте VST3 с VST3, Standalone
  со Standalone. Проверяйте сначала Single, затем привычный Multi-проект.
- Проиграйте 30–60 секунд в H8, запишите показания CPU в DAW и наличие
  заиканий. Повторите в C++, затем ещё раз в H8. Слушайте одинаковую
  громкость, атаки, хвосты, sustain, арпеджиатор и смену пресетов.
- Для каждого режима отдельно: **Setup → Performance diagnostics →
  Start new summary measurement**, проиграть партию, **Stop measurement**,
  **Save performance report…**. Сохраните `KS-H8.json` и `KS-Cpp.json`.
  Переключение контроллера останавливает текущую запись, чтобы режимы не
  смешивались. Новый замер нужно запускать после переключения.
- В JSON поле `controller_backend` содержит `original-h8` или
  `native-cpp-runtime`; внутри `session` указан режим именно записанного
  замера. Диагностика измеряет работу/ожидания и пропуски; её времена
  не являются процентом CPU из DAW. Финальное сравнение показаний DAW
  повторите с выключенной диагностикой.
- Сообщите DAW/версию, VST3 или Standalone, частоту и размер буфера,
  профиль Audio buffer, Single/Multi, число экземпляров, пресет,
  показания CPU и заикания в обоих режимах. Приложите два JSON;
  прошивку, ROM и банки передавать не нужно.

JIT, приоритеты, настройки Windows и выбор DSP-потоков этой сборкой
не переключаются. На локальном Intel предыдущая версия C++ экономила
около 2–5% процессорного времени в коротких офлайн-проверках. Результат
на Ryzen и устранение заиканий пока неизвестны — для этого и нужен тест.
